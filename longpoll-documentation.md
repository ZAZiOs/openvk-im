# Документация LongPoll API
## 1. Подключение (Получение данных сервера)

Для начала работы необходимо вызвать метод `messages.getLongPollServer`.

**Запрос:**
`GET /method/messages.getLongPollServer`

**Успешный ответ (JSON):**
```json
{
    "response": {
        "key": "a1b2c3d4...",
        "server": "https://api.openvk.org/nim",
        "ts": 1622548800,
        "pts": 12345
    }
}
```

* **key**: Секретный ключ сессии (валиден 12 часов).
* **server**: Адрес сервера для подключения.
* **ts**: Номер последнего события (Timestamp).
* **pts**: (Опционально) Идентификатор для получения истории через `messages.getLongPollHistory`.

---

## 2. Формирование запроса к серверу

Используя полученные данные, необходимо отправить GET-запрос по следующему шаблону:

`{server}?act=a_check&key={key}&ts={ts}&wait=25&mode={mode}&version={version}`

**Параметры запроса:**
| Параметр | Описание |
| :--- | :--- |
| **act** | Всегда `a_check`. |
| **key** | Ключ, полученный в `getLongPollServer`. |
| **ts** | Последний полученный номер события. |
| **wait** | Время ожидания в секундах (рекомендуется 25). |
| **mode** | Битовая маска дополнительных данных (см. ниже). |
| **version** | Версия протокола (рекомендуется 2). |

**Настройки Mode (Битовая маска):**
* `2`: Получать вложения (`attachments`).
* `8`: Получать расширенные данные о событиях.
* `32`: Возвращать `pts`.
* `64`: Получать доп. поле `extra_id`.

---

## 3. Формат ответа сервера (Envelope)

Сервер возвращает массив обновлений в поле `updates`. Каждое обновление представлено в виде массива, где первый элемент — **код события**.

```json
{
    "ts": 1622548900,
    "updates": [
        [4, 123, 1, 345, 1622548850, "", "Привет!", {  
            "attach1_type": "photo",
            "attach1": "ownerid_photoid",
        }]
    ],
    "pts": 12346
}
```

### Ошибки подключения:
* `{"failed": 1}` — История событий устарела. Нужно обновить `ts`.
* `{"failed": 2}` — Истек срок действия `key`. Нужно заново вызвать `getLongPollServer`.
* `{"failed": 3}` — Информация утеряна. Нужно обновить `key` и `ts`.

## 4. Таблица событий
Каждое событие приходит в массиве `updates`. Первым элементом всегда идет **ID события** (код).

> **Важно:** Поля со звездочкой (`*`) в таблице добавляются только при определенных битовых масках в `mode` при подключении. Например, `random_id` появляется только если включен бит `128`.

### Примечание по вложениям (Attachments)
Если в запросе передан флаг `mode=2`, в событиях **4** и **5** появляется объект `attachments*`. Пример структуры:

```json
{
  "attach1_type": "photo",
  "attach1": "123_456",
  "attach2_type": "doc",
  "attach2": "123_789",
  "emoji": "1" // если в сообщении есть эмодзи
}
```

### Базовые медиа-вложения
Для каждого вложения в объекте передается пара ключей, где `$i` — порядковый номер (начиная с 1).

| Поле | Пример значения | Описание |
| :--- | :--- | :--- |
| **attach{$i}_type** | `photo`, `video`, `audio`, `doc`, `wall`, `sticker`, `link` | Тип вложения. |
| **attach{$i}** | `123_456` | ID вложения в формате `{owner_id}_{item_id}`. |

### Специальные поля и метаданные
Помимо медиафайлов, объект может содержать системные флаги:

| Поле | Значение | Описание |
| :--- | :--- | :--- |
| **from** | `456123` | ID отправителя сообщения (всегда приходит в групповых чатах). |
| **fwd** | `1_10,1_11` | Список ID пересланных сообщений через запятую. |
| **emoji** | `1` | Флаг того, что сообщение содержит только Emoji. |
| **title** | `Тема письма` | Заголовок сообщения (используется для Email-переписки или старых чатов). |
| **geo** | `12345` | ID гео-метки. |

### Ссылки (тип `link`)
Если `attach{$i}_type` равен `link`, передаются дополнительные поля:
* **attach{$i}_url**: Прямая ссылка.
* **attach{$i}_title**: Название страницы.
* **attach{$i}_desc**: Краткое описание.
* **attach{$i}_photo**: ID фотографии-превью.

## 5. Флаги
### Флаги сообщений (битовая маска)

Флаги используются в событиях с кодом `1`, `2`, `3`, `4` и `5` для описания состояния сообщения. Чтобы проверить наличие флага, нужно выполнить побитовое **И** (`&`) между значением из события и константой флага.

| Флаг | Битовое значение | Константа (hex) | Описание |
| :--- | :--- | :--- | :--- |
| **Unread** | 1 | `0x0001` | Сообщение не прочитано. |
| **Outbox** | 2 | `0x0002` | Исходящее сообщение (отправлено текущим пользователем). |
| **Replied** | 4 | `0x0004` | На сообщение был дан ответ. |
| **Important** | 8 | `0x0008` | Сообщение отмечено как «Важное» (звездочка). |
| **Chat** | 16 | `0x0010` | Сообщение отправлено через чат. |
| **Friends** | 32 | `0x0020` | Сообщение от друга (актуально только для классического VK). |
| **Spam** | 64 | `0x0040` | Сообщение помечено как спам. |
| **DeleteForAll** | 64 | `0x0040` | Сообщение удалено для всех участников (OpenVK специфика). |
| **Deleted** | 128 | `0x0080` | Сообщение удалено (в корзине). |
| **Fixed** | 256 | `0x0100` | Сообщение проверено пользователем на спам. |
| **Media** | 512 | `0x0200` | Сообщение содержит вложения (фото, видео, аудио). |
| **Hidden** | 65536 | `0x10000` | Приветственное сообщение от сообщества. |

### Флаги диалогов (Chat Flags)

Эти флаги приходят в событиях `10`, `11`, `12` и относятся к состоянию всего чата/диалога целиком.

| Флаг | Значение | Описание |
| :--- | :--- | :--- |
| **Important** | 1 | Диалог отмечен как важный. |
| **Unanswered** | 2 | В диалоге есть неотвеченные сообщения. |
