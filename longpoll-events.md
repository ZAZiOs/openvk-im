# User Long Poll API

`{$server}?act=a_check&key={$key}&ts={$ts}&wait=25&mode=2&version=2`

| Параметр | Описание |
|---------|-----------|
|key | Секретный ключ сессии. |
|server | Адрес сервера (начинается с https://). |
| ts |Номер последнего события, начиная с которого нужно получать данные. |
| wait |Время ожидания. Максимальное значение — 90. Так как некоторые прокси-серверы обрывают соединение после 30 секунд, мы рекомендуем указывать wait= 25. |
| mode |Дополнительные опции ответа. Сумма кодов опций из списка: **2** — получать вложения. **8** — возвращать расширенный набор событий. **32** — возвращать pts (это требуется для работы метода messages.getLongPollHistory без ограничения в 256 последних событий). **64** — в событии с кодом 8 (друг стал онлайн) возвращать дополнительные данные в поле $extra (смотрите Структура событий). **128** — возвращать поле random_id (random_id может быть передан при отправке сообщения методом messages.send).
| version | Версия. Актуальная версия: 3. Для версии 0 (по умолчанию) идентификаторы сообществ будут приходить в формате group_id + 1000000000 для сохранения обратной совместимости. Мы рекомендуем использовать актуальную версию. |

Для первого запроса в рамках сессии значения для параметров server, key и ts необходимо получить методом messages.getLongPollServer. В последующих запросах используйте те же server и key и новое значение ts, которое придет вам в ответе от Long Poll сервера.

**Что возвращает longpoll api:**

```json
{
    "ts": 1820350874,
    "updates": [
        [4, 1619489, 561, 123456, 1464958914, "hello", {
            "title": "... "
        }, {
            "attach1_type": "photo",
            "attach1": "123456_414233177",
            "attach2_type": "audio",
            "attach2": "123456_456239018"
        }]
    ]
}
```

ts - integer - Номер последнего события. Используйте его в следующем запросе.
updates - array
Массив, элементы которого содержат представление новых событий (каждый элемент также является массивом). Длина массива updates может быть равна 0 (это означает, что за время wait новых событий не произошло).

**В ответ на запрос сервер может вернуть одну из ошибок:**
```json
{
 "failed": 1,
 "ts": "{new_ts}"
},
{
 "failed": 2
},
{
 "failed": 3
},
{
 "failed": 4,
 "min_version": 0,
 "max_version": 1
}
```
| Флаг | Описание |
|------|----------|
| `"failed":1` | История событий устарела или была частично утеряна, приложение может получать события далее, используя новое значение ts из ответа. |
| `"failed":2` | Истекло время действия ключа, нужно заново получить key методом messages.getLongPollServer. |
| `"failed":3` | Информация о пользователе утрачена, нужно запросить новые key и ts методом messages.getLongPollServer. |
| `"failed":4` | Передан недопустимый номер версии в параметре version. |

## Структура флагов
Флаг это единое число uint64 в котором применяется побитовая маска
### Флаги сообщений

| Bit (Dec) | Constant / Name | Binary (8-16-24 bit) | Description |
| :--- | :--- | :--- | :--- |
| **1** | `UNREAD` | `00000001` | Сообщение не прочитано. |
| **2** | `OUTBOX` | `00000010` | Исходящее сообщение. |
| **4** | `REPLIED` | `00000100` | На сообщение был создан ответ. |
| **8** | `IMPORTANT` | `00001000` | Помеченное сообщение (звездочка/важное). |
| **16** | `CHAT` | `00010000` | **[Deprecated]** Отправлено через чат. |
| **32** | `FRIENDS` | `00100000` | Отправлено другом (не для бесед). |
| **64** | `SPAM` | `01000000` | Помечено как спам. |
| **64** | `DELETE_FOR_ALL` | `01000000` | **[v3+]** Удалено для всех получателей. |
| **64** | `NOT_DELIVERED` | `01000000` | Входящее сообщение не доставлено (TTL). |
| **128** | `DELETED` | `10000000` | Сообщение удалено (находится в корзине). |
| **256** | `FIXED` | `00000001 00000000` | **[Deprecated]** Проверено пользователем на спам. |
| **512** | `MEDIA` | `00000010 00000000` | **[Deprecated]** Содержит медиаконтент. |
| **65536** | `HIDDEN` | `00000001 00000000 00000000` | Приветственное сообщение (не поднимает диалог вверх списка). |

### Флаги диалогов
| Bit (Dec) | Constant / Name | Binary (8-16-24 bit) | Description |
| :--- | :--- | :--- | :--- |
| **1** | `IMPORTANT` | `00000001` | Важный диалог. |
| **2** | `UNANSWERED` | `00000010` | Неотвеченный диалог. Обратите внимание, для версий <2 значение флага противоположно — диалог с ответом от сообщества. |

## Дополнительные описания переменных

| Переменная | Тип | Описание |
| :--- | :--- | :--- |
| **$peer_id** | `integer` | Назначение: `id` (пользователь), `2000000000 + id` (беседа), `-id` или `1000000000 + id` (сообщество). |
| **$flags / $mask** | `integer` | Битовая маска состояния сообщения по таблице выше |
| **$timestamp** | `integer` | Время события в формате Unixtime. |
| **$attachments** | `array` | Массив объектов вложений (передается, если `mode >= 2`). |
| **$random_id** | `integer` | Поле для проверки уникальности, переданное при отправке. |
| **$extra_fields** | `object` | Дополнительные поля (например, `from_id`, данные о платформе, `payload`). |


## События в формате JSON

Ниже представлены структуры массивов, которые приходят в поле `updates`.

### 1. Флаги сообщений (Коды 1-3)
Используются для синхронизации состояния (прочитано, удалено, важное).
* **Код 1 (Замена):** `[1, $message_id, $flags, $peer_id]`
* **Код 2 (Установка):** `[2, $message_id, $mask, $peer_id]`
* **Код 3 (Сброс):** `[3, $message_id, $mask, $peer_id]`

### 2. Новое сообщение (Код 4)
Самое частое событие. Содержит полный объект сообщения.
```json
[
  4,
  $message_id,
  $flags,
  $peer_id,
  $timestamp,
  $text,
  { "$attachments": "..." },
  $random_id,
  $extra_fields
]
```

### 3. Редактирование сообщения (Код 5)
```json
[
  5,
  $message_id,
  $mask,
  $peer_id,
  $timestamp,
  $new_text,
  $attachments,
  0
]
```

### 4. Чтение сообщений (Коды 6-7)
* **Код 6 (Входящие):** `[6, $peer_id, $local_id]` — всё до `$local_id` прочитано получателем.
* **Код 7 (Исходящие):** `[7, $peer_id, $local_id]` — всё до `$local_id` прочитано нами.

### 5. Статус Online/Offline (Коды 8-9)
* **Код 8 (Online):** `[8, -$user_id, $extra, $timestamp]`
    > В `$extra` младший байт — это ID платформы.
* **Код 9 (Offline):** `[9, -$user_id, $flags, $timestamp]`
    > `$flags`: 0 — выход, 1 — таймаут.

### 6. Удаление и восстановление (Коды 13-14)
* **Код 13 (Удаление):** `[13, $peer_id, $local_id]`
* **Код 14 (Восстановление):** `[14, $peer_id, $local_id]`

### 7. Активность в чате (Коды 61-64)
* **Код 61:** `[61, $user_id, $flags]` — печатает в ЛС.
* **Код 62:** `[62, $user_id, $chat_id]` — печатает в беседе.
* **Код 63:** `[63, "$user_ids", $peer_id, $total_count, $ts]` — несколько печатающих.
* **Код 64:** `[64, "$user_ids", $peer_id, $total_count, $ts]` — записывают аудио.

### 8. Настройки и счетчики (Коды 80, 114)
* **Код 80 (Счетчик):** `[80, $count, 0]` — общее кол-во непрочитанных в меню.
* **Код 114 (Уведомления):** `[114, $peer_id, $sound, $disabled_until]`

---

### Примечание по $extra_fields
Это динамический объект. В коде 4 он часто содержит:
* `from`: ID отправителя (если это беседа).
* `source_act`: Тип системного действия (invite, kick).
* `source_mid`: ID пользователя, над которым совершено действие.
* `payload`: JSON-строка из кнопок клавиатуры.
